# AutoDoc OS Tracker

Telegram Mini App + бот для трекинга пиков OS/PA/SIO/PC, расчёта премии, зарплаты и графика смен.
Теперь с **общим рейтингом** — сотрудники соревнуются по премии за месяц.

## Компоненты

| Файл | Что делает |
|------|-----------|
| `index.html` | Telegram Mini App (хостится на GitHub Pages). Данные — в localStorage. |
| `bot.py` | Telegram-бот (pyTelegramBotAPI). Меню, ввод смен, `/rating`, рассылка. |
| `supabase/schema.sql` | Полная схема базы (рейтинг, рейтинг пасьянса, согласия, реестр бота) + RLS. Один скрипт, поднимает базу с нуля. |
| `supabase/functions/submit-rank/` | Edge Function: проверяет подпись Telegram и пишет в таблицу. |
| `supabase/functions/durak/` | Edge Function: комнаты всех сетевых игр. `engine.ts` — дурак, `poker.ts` — холдем, `blackjack.ts` — «21», `domino.ts` — домино, `sea.ts` — морской бой, `index.ts` — комнаты и проверка ходов. |

## 🏆 Рейтинг (соревнование)

Каждый юзер шлёт свои месячные итоги (премия, пики, смены, ppc) в общую таблицу
Supabase `leaderboard`. И Mini App, и бот читают из неё топ.

- **Mini App** — вкладка «🏆 Рейтинг»: топ по бонусу за месяц, свой ряд подсвечен,
  переключение месяцев ‹ ›.
- **Бот** — кнопка «🏆 Рейтинг» в меню или команда `/rating` (`/top`).

Ключ рейтинга — **премия за месяц (zł)**. Строка на юзера в месяц (`primary key (uid, month)`),
обновление через upsert.

### 🃏 Пасьянс и его рейтинг

Вкладка «Карты» → «Косынка» — игра целиком на клиенте: правила, счёт, отмена,
автосбор, сохранение незаконченной партии в localStorage.

**Раздаются только выигрываемые расклады.** Случайная раздача «Косынки»
нередко не проходится в принципе, и это ощущается как несправедливость, а не
как сложная партия. Поэтому `solNew` перебирает раздачи и берёт первую, для
которой `solSolvable` нашёл выигрыш: перебор с запоминанием позиций, лимит по
узлам и по времени (обычно хватает 2–3 попыток и десятков миллисекунд). Если
за отведённое время ничего не нашлось, берётся последняя — хуже прежнего не
будет.

Базы закреплены за мастями: туз ложится только в клетку своей масти, как она
и подписана. Веер сброса раскрыт настолько, чтобы у накрытых карт читались
достоинство и масть.

Победы попадают в общий топ — см. раздел «Рейтинг по картам» ниже. Если базы
нет или связь пропала, свои победы всё равно видны: они считаются на
устройстве и уедут в топ при следующем открытии вкладки.

### 🂡 Дурак онлайн

Вкладка «Карты» → «Дурак». Столы на **2, 3 или 4 игроков** прямо в боте.
Состояние партии целиком на сервере: клиент получает только свои карты и
количество карт у соседей, а каждый ход проверяется движком — сходить не по
правилам или подсмотреть чужую руку нельзя. Таблица `durak_rooms` приватная,
анон-ключ к ней доступа не имеет; uid соседей клиенту тоже не отдаётся.

**Живые столы.** В лобби список всех столов, которые сейчас ждут игроков:
видно, кто сидит и сколько мест осталось. Жмёшь «Зайти» — садишься, без
приглашений и заявок. Стол пропадает из списка, как только собрался.

**Приглашения** (когда нужен конкретный человек). Создатель жмёт «Позвать в
Telegram» — уходит ссылка `t.me/<бот>?start=dk_КОД`. Она открывает мини-апп
сразу за этим столом. Можно и просто продиктовать код — в лобби есть поле
«Войти по коду».

**Уведомления.** Когда кто-то садится за твой стол, функция шлёт сообщение в
бот с кнопкой «За стол» — приходит, даже если приложение свёрнуто.

**Правила на троих-четверых:** подкидывать может любой, кроме защитника, и
только ранги, уже лежащие на столе; розыгрыш закрывается, когда всё отбито и
все сказали «бито»; «беру» заканчивает розыгрыш сразу; кто остался без карт
при пустой колоде — вышел, дурак остаётся один.

Чтобы ссылка формировалась, впиши имя бота в `index.html`:

```js
const BOT_USERNAME = 'имя_бота';   // без @
```

Без этого приглашение копирует код в буфер — играть можно, просто на шаг длиннее.

### Тесты

Гоняются без сети, Supabase и Telegram — всё подменяется заглушками.

```bash
node tests/run-engine.mjs                  # правила «дурака» на 2–4 игроков
node tests/run-poker.mjs                   # холдем + перебор всех комбинаций
node tests/run-blackjack.mjs               # «21»: выплаты, сплит, дилер
node tests/run-domino.mjs                  # домино: раздача, базар, рыба, счёт
node tests/run-sea.mjs                     # морской бой: флот, стрельба, 1×1 и 2×2
node tests/run-rates.mjs                   # ставки: приложение и бот не разъехались
node tests/run-function.mjs                # Edge Function целиком, пять игр
PYTHONPATH=. python3 tests/test_broadcast.py   # рассылка объявлений
npm i playwright && node tests/run-app.mjs  # столы в настоящем браузере
node tests/app_solitaire.mjs               # «Косынка» там же
```

Браузерный прогон поднимает локальную копию Edge Function, открывает
приложение в трёх вкладках и играет втроём. Заодно щупает карты в местах
нахлёста: надпись нижней карты не должна проступать сквозь верхнюю.

### ♠ Покер (техасский холдем)

Вкладка «Карты» → «Покер». Столы на **2–5 игроков**, без лимита, фишки
игровые. Как и в «дураке»: список живых столов, вход без приглашений,
уведомление в бот, когда стол собрался.

Реализовано по правилам: блайнды 10/20 и кнопка дилера по кругу, хедз-ап по
своим правилам, минимальный рейз равен предыдущему повышению, олл-ин меньше
полного рейза торговлю не переоткрывает, побочные банки по уровням вложений,
делёж поровну с остатком ближайшему к кнопке.

Оценщик рук (`poker.ts`) проверен полным перебором: все **2 598 960**
пятикарточных комбинаций распределяются ровно по табличным частотам —
1 302 540 старших карт, 1 098 240 пар, … 40 стрит-флешей.

### 🂱 «Двадцать одно»

Вкладка «Карты» → «21». Против дилера, **одному или компанией до пяти**.
Стол на одного начинается сразу — ждать некого.

Шесть колод и перетасовка каждый раунд, туз 11 или 1, блэкджек только с двух
карт и платит 3:2, дилер добирает до 17 и стоит на мягких 17, удвоение на
первых двух картах, сплит один раз (разделённые тузы получают по одной карте).
Страховки и сдачи нет намеренно — так и написано в правилах внутри игры.

**Фишки живут на сервере, а не в партии.** Каждый игровой день выдаётся
**30 000** фишек; день считается по Щецину и начинается в **02:00** (в 01:59
идёт ещё вчерашний). Баланс лежит в таблице `wallets`, выдаёт и меняет его
только функция `wallet_apply` — из приложения накрутить себе фишек нельзя.

Ставка делается ползунком и кнопками **×1 ×2 ×3**: ползунок задаёт размер,
кнопка — во сколько раз его умножить и сразу поставить. Отдельной кнопки
«поставить» нет, ×1 — это она и есть; кратность, на которую не хватает фишек,
гаснет, а не обрезается молча.

Баланс один на все столы, и списывается он **в момент ставки**, а не по итогу
раунда: иначе можно было бы сесть за два стола и поставить один и тот же запас
дважды. Стеки за столом при каждом ходе подтягиваются к кошельку, так что
подменённое состояние партии всё равно затрётся настоящим балансом.

### 🁣 Домино

Вкладка «Карты» → «Домино». Набор **дубль-шесть** (28 костей), столы на
**2, 3 или 4 игроков**, партия до **101 очка**. Лобби, живые столы и
уведомления в бот — те же, что у остальных сетевых игр. В самом боте —
команда `/domino` или кнопка «🁣 Домино» в меню; приглашение уходит ссылкой
`t.me/<бот>?start=dm_КОД`.

Канон, который зашит в `domino.ts`:

- на двоих раздаётся по **7** костей, на троих-четверых по **5**, остальное
  уходит в **базар**;
- первый кон начинает владелец **младшего дубля** и обязан положить именно
  его; дублей нет ни у кого — ходит младшая кость по сумме очков;
- следующие коны начинает победитель предыдущего и кладёт что хочет;
- кость прикладывается к любому из двух концов цепочки совпадающим числом;
- нечем ходить — **тянешь из базара**, пока не попадётся подходящая, и ход
  остаётся за тобой; базар пуст, а ходить нечем — **пас**;
- спасовали все подряд — **рыба**;
- поле — **квадрат 11×11 клеток**, а не прямая полоса: цепочка вьётся по нему
  так, как её ведут игроки;
- за выход дают сумму очков, оставшихся у соперников; при рыбе выигрывает тот,
  у кого очков меньше всех, и берёт разницу между чужими очками и своими.
  Меньше всех поровну у нескольких — кон ничейный.

Кости соседей, как и карты, лежат на сервере: клиенту приходит только своя
рука и **сколько** костей у кого. Базар тоже закрыт — видно лишь его размер.

**Поле и расстановка руками.** Стол — квадрат 11×11 клеток, весь помещается на
экран целиком. Ход в два касания: тычешь в кость у себя в стопке (она
приподнимается, на поле загораются клетки, куда её можно положить), потом
тычешь в клетку. Передумал — жмёшь по кости ещё раз.

Самая первая кость кона ложится в центр, дальше клетку выбирает игрок: любую
свободную вплотную к нужному концу. Логически цепочка остаётся одной линией
(`line[i].b === line[i+1].a`), клетка задаёт только положение и поворот. Кость
поворачивается так, чтобы половина, которой она цепляется, смотрела на соседа;
дубли встают **поперёк**. Между соседями по цепочке рисуется ниточка — на
повороте кости стоят под углом и сами не смыкаются, а так видно, куда цепочка
идёт. Концы обведены жёлтым.

Клетку проверяет сервер, а не приложение: положить кость можно только вплотную
к тому концу, к которому она подходит, и только в свободную клетку внутри поля.
Если завести цепочку в угол и обложить конец со всех сторон, класть туда станет
некуда — подходящая по числу кость просто перестанет предлагаться, а игрок
пойдёт в базар или спасует.

Клетка, примыкающая сразу к обоим концам, спрашивает, к какому цепляем: от
этого зависит, какое число останется открытым. На пустом поле и при одинаковых
концах вопрос не задаётся — выбор там ничего не меняет.

Движок прогоняется на 120 случайных партиях (по 40 на 2, 3 и 4 игроков), причём
клетка каждый раз берётся случайная: все доигрываются до 101 очка, цепочка ни
разу не рвётся, кости не налезают друг на друга и не уходят за край, соседи по
цепочке всегда лежат вплотную, все 28 костей на месте — в руках, в базаре или
на поле.

### 🚢 Морской бой

Вкладка «Карты» → «Морской бой». **Один на один** или **двое на двое**, правила
школьные, без выдумок. Лобби, живые столы и уведомления в бот — те же, что у
остальных сетевых игр. В боте — команда `/sea` или кнопка «🚢 Морской бой» в
меню; приглашение уходит ссылкой `t.me/<бот>?start=mb_КОД`.

Что зашито в `sea.ts`:

- поле **10×10** у каждого игрока;
- флот: **1 линкор** (4 клетки), **2 крейсера** (3), **3 эсминца** (2),
  **4 катера** (1) — десять кораблей на двадцать клеток;
- корабль стоит по прямой, без разрывов, целиком внутри поля;
- корабли **не соприкасаются** — ни боком, ни углом;
- **попал или убил — стреляешь снова**, промахнулся — ход к сопернику;
- вокруг убитого корабля клетки открываются как пустые: по правилу о
  несоприкосновении там ничего и не может стоять;
- выигрывает тот, кто первым потопил весь флот соперника.

**Расстановка руками.** Внизу выбираешь корабль и как он ляжет — вдоль или
поперёк; жмёшь по клетке — корабль встаёт оттуда, жмёшь по уже стоящему — он
возвращается в запас. Есть «Авто» и «Очистить». Бой начинается, когда готовы
все.

**Расстановку проверяет сервер.** Клиент рисует её сам и подсказывает, куда
можно ставить, но решает `sCheckFleet`: состав флота, прямизна, разрывы, выход
за поле, наложение и касание углами. Прислать «флот» из одних линкоров не
выйдет.

**Чужие корабли в телефон не приходят вообще** — ни координаты, ни количество
попаданий. Клиент видит только пометки по клеткам (мимо / ранен / убит); целые
корабли соперника появляются в ответе, лишь когда их потопили.

**Двое на двое:** у каждого из четверых своё поле, команды сидят через одного
(места 1 и 3 против 2 и 4). Поле напарника видно целиком. Стрелять можно по
любому живому полю соперников — сверху выбираешь, по чьему бьёшь. Внутри
команды ходят по очереди; у кого флот потоплен, тот больше не стреляет.
Команда проигрывает, когда потоплены оба её флота.

Движок прогоняется на 60 случайных партиях (по 30 на 1×1 и 2×2) со случайной
расстановкой и случайными выстрелами: все доигрываются, пометки на поле никогда
не расходятся с попаданиями по кораблям, победа объявляется только когда флот
соперника действительно на дне. Отдельно — 300 случайных расстановок, каждая
проходит серверную проверку.

### ★ «Что нового»

При входе в приложение один раз на каждое обновление всплывает окно со списком
того, что добавилось в играх и рейтинге: строки выезжают по очереди, иконки
всплывают следом, новинки помечены значком. Жмёшь по строке — открывается сразу
нужная игра.

Версия хранится в `NEWS_V`; человек видел её или нет — в `DB.newsSeen`
(localStorage, то есть **на устройство**, а не на аккаунт). Отметка ставится
**при закрытии**, а не при показе: свёрнутое на полпути приложение не съест
новость. Поменял `NEWS_V` и список `NEWS` — окно всплывёт у всех заново. Тем,
кого позвали за стол по ссылке, окно не мешает: приглашение важнее.

То же самое один раз приходит **в самом боте** на `/start` — отдельным
сообщением с кнопками. Отметка лежит в `os_data.json` рядом с остальными
данными человека (`user["news"]`), отдельной колонки в базе ради этого не
заводили.

### 🏆 Рейтинг по картам

«Рейтинг» → вкладка **«Карты»**, внутри подвкладка на каждую игру: косынка,
дурак, покер, «21», домино, морской бой. У каждой свой смысл победы — партия
собрана, не остался дураком, забрал все фишки за столом, закрыл раунд в плюс,
добрал до 101 очка, потопил весь флот соперника.

Всё лежит в одной таблице `game_stats` (строка на «игрок × игра»):

- **косынка** считается на устройстве и приезжает через `submit-rank` в
  `sol_leaderboard`, откуда триггером зеркалится в `game_stats` — поэтому
  вторую функцию передеплоивать не пришлось;
- **сетевые игры** пишет сама Edge Function по итогу партии. Клиент в этом
  не участвует вовсе: он видит только свои карты и не должен иметь
  возможности приписать себе победу.

Начисление идёт через `bump_game_stats(jsonb)` — функция шлёт **прибавки**, а
не итоги, иначе два стола, закончившихся одновременно, затёрли бы счёт друг
другу. Права на неё выданы только `service_role`.

### 📖 Правила для новичков

В каждой игре есть кнопка «Правила» (и в лобби, и в шапке). Там разобрано,
как идёт раздача и что делает каждая кнопка, а комбинации показаны
**настоящими картами**, а не текстом — в покере все девять, от стрит-флеша до
старшей карты, в «21» — сколько стоит каждая карта, в домино — настоящими
костями, что к чему сходится, а что нет. В морском бое разобраны состав флота,
несоприкосновение и порядок хода.

### Как задеплоить функции

Нужно один раз после правок в `supabase/functions/`.

**Через браузер, без терминала.** Supabase → Edge Functions → создать функцию
с именем `durak` → вставить содержимое `supabase/functions/durak/index.bundled.ts`
(это те же engine.ts и index.ts, сложенные в один файл специально для вставки) →
Deploy. Так же для `submit-rank`, только там вставляется обычный `index.ts`.
Затем Edge Functions → Secrets добавить три значения:

```
BOT_TOKEN        = токен от @BotFather
PROJECT_URL      = https://mkuwkntdcpfsxhqblkic.supabase.co
SERVICE_ROLE_KEY = service_role из Settings → API
```

**Через терминал.** Нужен установленный Supabase CLI:

```bash
supabase login                                    # откроет браузер
supabase link --project-ref mkuwkntdcpfsxhqblkic
supabase functions deploy durak --no-verify-jwt
supabase functions deploy submit-rank --no-verify-jwt
supabase secrets set BOT_TOKEN=... PROJECT_URL=... SERVICE_ROLE_KEY=...
```

CLI сам заберёт всю папку функции, поэтому `index.bundled.ts` ему не нужен.

Проверить, что функция жива: Edge Functions → durak → Logs. При заходе в игру
там появятся запросы.

`--no-verify-jwt` обязателен: функции проверяют не JWT Supabase, а подпись
Telegram, поэтому встроенную проверку надо отключить.

### Если функция не отвечает

Открой адрес функции в обычном браузере — по ответу сразу видно причину:

```
https://mkuwkntdcpfsxhqblkic.supabase.co/functions/v1/durak
https://mkuwkntdcpfsxhqblkic.supabase.co/functions/v1/submit-rank
```

| Ответ | Причина |
|---|---|
| `method` (405) | функция жива и настроена верно |
| `{"code":"NOT_FOUND"}` | не задеплоена или названа иначе (регистр важен) |
| `Invalid JWT` (401) | не выключен Verify JWT |
| `BOOT_ERROR` (503) | вставлен `index.ts` вместо `index.bundled.ts` — в обычном файле есть `import "./engine.ts"`, а соседнего файла в редакторе нет |

Важно: все эти ошибки отдаёт шлюз Supabase, а не код функции, и CORS-заголовков
в них нет. Браузер такой ответ выбрасывает, поэтому в приложении `fetch`
падает раньше, чем удастся прочитать код ответа — в игре видно только
«Сервер есть, но функция durak не отвечает». Это сообщение означает ровно
то же, что и `NOT_FOUND` по ссылке выше: до кода функции запрос не дошёл.

Если функция развёрнута и отвечает `method`, а игра всё равно ругается —
смотри Edge Functions → durak → Logs: там уже будут ошибки самого кода
(чаще всего не заданы секреты `BOT_TOKEN` / `PROJECT_URL` / `SERVICE_ROLE_KEY`).

### Настройка Supabase (один раз)

1. Создай проект на [supabase.com](https://supabase.com).
2. SQL Editor → выполни `supabase/schema.sql` (создаёт все таблицы и RLS; скрипт идемпотентный).
3. Settings → API → возьми **Project URL** и **publishable/anon key**.
4. Пропиши их:
   - в `index.html` → константы `SB_URL`, `SB_KEY`;
   - боту → переменные окружения `SUPABASE_URL`, `SUPABASE_KEY`.

### Пересоздание базы (если проект Supabase потерян)

База восстанавливается сама — вручную ничего переносить не нужно.

1. Создай новый проект Supabase, выполни `supabase/schema.sql`.
2. Пропиши новые `SB_URL` / `SB_KEY` в `index.html`, `SUPABASE_URL` / `SUPABASE_KEY`
   и `SUPABASE_SERVICE_KEY` — боту, и передеплой Edge Function `submit-rank`
   с секретами (`BOT_TOKEN`, `PROJECT_URL`, `SERVICE_ROLE_KEY`).
3. Подними `DB_GEN` в `index.html` на следующее число.

После этого каждый, кто откроет Mini App, один раз зальёт в новую базу всё,
что есть у него на устройстве: текущий месяц (сырые записи) и итоги прошлых
месяцев из локального архива `DB.archive`, плюс заново зафиксирует уже
принятое согласие. `bot_users` наполняется при `/start` и сидом из рейтинга.

**Что восстановить нельзя:** месяцы, которых нет ни у кого в локальном архиве.
Архив ведётся с версии, где появился `DB.archive` — всё, что было очищено
`pruneOldMonths` до неё, жило только на сервере и утеряно вместе с базой.

### Защита записи (только реальные Telegram-юзеры)

Клиент **не пишет в таблицу напрямую** — RLS это запрещает. Запись идёт через
Edge Function `submit-rank`, которая проверяет HMAC-подпись Telegram `initData`,
берёт доверенный `uid` из подписанных данных и пишет service-ролью.
Подделать чужой `uid` или спамить не из Telegram нельзя.

```bash
# Supabase CLI
supabase functions deploy submit-rank --no-verify-jwt
supabase secrets set \
  BOT_TOKEN=<токен_бота> \
  PROJECT_URL=https://<ref>.supabase.co \
  SERVICE_ROLE_KEY=<service_role_key>   # Settings → API → service_role (СЕКРЕТ, не в git!)
```

> `service_role` ключ живёт только в секретах функции — в клиент/репо не попадает.
> `--no-verify-jwt`, потому что авторизация своя (проверка Telegram-подписи).
> Анти-накрутка чисел (пересчёт бонуса на сервере из сырых смен) — отдельный шаг, можно добавить позже.

## Рассылка (admin-only)

Бот ведёт реестр пользователей в таблице `bot_users` и умеет рассылать.

- `/start` — регистрирует/реактивирует пользователя.
- `/stats` — сколько активных (только админ).
- `/broadcast текст` — разослать всем активным (только админ). Заблокировавшие бота → `active=false`.

Нужно:
1. Выполнить `supabase/schema.sql` (в нём есть `bot_users` + перенос uid из рейтинга).
2. Railway → Variables:
   - `ADMIN_TELEGRAM_IDS` — твой Telegram ID (через запятую, если несколько).
   - `SUPABASE_SERVICE_KEY` — **service_role** ключ (Settings → API). Секрет, только в env, не в код/репо.

Без `SUPABASE_SERVICE_KEY` рассылка/статы отключены (бот пишет реестр service-ролью, обходя RLS).
